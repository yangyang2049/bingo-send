# 使用指南

继续用豆包或其他输入法输入，在正文末尾说出你选择的口令，默认为 **Bingo**；文字上屏并稳定后，Bingo Send 检测口令、读回核验当前输入内容，再触发目标应用的发送快捷键。**默认原样保留正文和口令并发送**，也可使用下文介绍的可选移除模式。

例如，默认保留模式下：输入 `帮我检查页面，Bingo。` → 发送完整的 `帮我检查页面，Bingo。`

适用于 macOS 13 及以上，Swift 5.9 及以上，无第三方依赖。下载安装包前请查看对应 Release 标注的架构及签名、公证状态。

## 快速上手

1. 将 `Bingo Send.app` 放到你准备长期使用的位置，例如“应用程序”，然后打开。若系统阻止首次启动，请按 macOS 的常规方式在系统设置中允许打开。
2. 在 Bingo Send 中点“去授权…”，由你亲自在 **系统设置 → 隐私与安全性 → 辅助功能** 中开启 Bingo Send。授权用于读取聚焦输入框及光标状态，并发出发送按键。
3. 打开“应用预设”页，或点“启用范围”里的“从常用预设添加…”，选择已安装的桌面应用或网站对应的浏览器配置，核对发送按键：`Return`、`⌘ Return` 或 `⌃ Return`。也可通过“手动添加应用…”选择 `.app`。
4. 网页预设会让你选择已安装的浏览器，并在添加前预览合并后的允许域名。手动配置时请打开“按网页域名限制”，每行填写一个域名，不加 `https://` 和路径，例如 `chat.deepseek.com`、`huggingface.co`。这些是配置建议，不代表已验证兼容。
5. 在设置中通过“选择常用口令”选择一个口令，或直接填写自定义“句尾口令”。保持“只检测，不发送”，再打开“启用口令发送”。切到目标输入框，输入一条**新的**测试内容；若选择 Bingo，可用 `你好，Bingo。`，把光标留在末尾。检测成功会有提示音和状态记录，文字保持原样。
6. 检测成功后，先保持“发送前移除句尾口令”关闭，再关闭“只检测，不发送”，输入一条无关紧要的新内容，核对目标应用是否真正发送成功。每个应用或网站都应单独试一次；需要移除模式时，再单独开启并验证。

全新安装的应用列表默认全部关闭，默认只检测；预设需由你主动添加。已有口令、应用规则、只检测开关和发送键等保存配置保持原样，不迁移、不覆盖。每次启动都会处于暂停状态；菜单栏纸飞机图标可以打开设置、启用、暂停或退出。

## 应用和网站预设

“应用预设”页提供 13 个条目，可按名称搜索，或筛选“国外”“国内”分组。预设帮助填写应用与网站范围，不代表输入框已验证兼容，也不会安装其他软件。

| 预设 | 可用配置方式 |
| --- | --- |
| Codex / ChatGPT | 已安装的 Codex 桌面应用；`chatgpt.com` |
| Claude / Claude Code | `claude.ai`；手动选择桌面应用 |
| Gemini | `gemini.google.com` |
| Grok | `grok.com` |
| Cursor | `cursor.com` 云端 Agent；手动选择桌面应用 |
| HuggingChat | `huggingface.co` 中的 HuggingChat |
| DeepSeek / DeepSeek Harness | 已安装的 Harness 桌面应用；`chat.deepseek.com` |
| ZCode（智谱） | 手动选择桌面应用 |
| Kimi | `www.kimi.com`、`www.kimi.ai`；手动选择桌面应用 |
| Kimi Code | 手动选择桌面应用 |
| WorkBuddy | 已安装的桌面应用 |
| Qoder CN | 已安装的国内版桌面应用；其他版本可手动选择 |
| TRAE CN | 已安装的国内版桌面应用；其他版本可手动选择 |

对于原生应用，已知应用标识且在本机找到时，“添加…”菜单会列出对应桌面应用。选中后，在配置窗口核对启用状态和发送键，再点“保存”。未找到时可用“手动选择桌面应用…”。预设不会下载应用；Claude Code、Kimi Code 等工具的终端 CLI 不包含在此预设覆盖范围内。

对于网页，选择“网页版 · 选择浏览器…”，选定已安装的浏览器，核对本次加入的网站及合并后的允许范围，再点“添加到启用范围”。预设会追加并去重域名，保留已有条目，打开域名限制并启用该浏览器规则。你可在同一窗口选择发送键，**同一浏览器的所有允许网站共用这个发送键**；再次添加预设会保留已有域名，但可能改变共用发送键。域名限制匹配网站主机及子域名，不细分网址路径。没有检测到浏览器时，请先安装浏览器，或在设置中手动添加。

## 能用于哪些输入框

原生应用、Electron 应用和浏览器网页都可以加入名单，但不是所有输入框都能工作。WorkBuddy、DeepSeek、Hugging Face 及其他 Agent 需要逐个验证。

输入框必须通过 macOS 辅助功能接口公开可读取的文本值（`AXValue`）和光标/选区状态，以便确认光标在正文末尾。默认保留模式不要求辅助功能属性可写，不修改草稿或选区；可选移除模式还需要编辑器支持辅助功能编辑，保留模式成功不代表移除也可用。默认只识别多行文本框；确认聊天框确实是单行控件时，可在该应用配置里打开“允许单行输入框”。自绘编辑器、部分网页编辑器，以及无法确认当前网页域名的浏览器窗口可能无法使用。

工具仅处理已启用应用中当前聚焦的输入框。程序已识别的浏览器强制检查允许的域名或其子域名；未识别的浏览器请在配置中手动打开“按网页域名限制”。切换应用、输入框、设置或光标位置会取消等待中的触发；进入输入框时已有的草稿只作为初始状态，不会立即发送，需要再输入新内容。

语音浮层短暂切走焦点时，工具会取消待发动作，并在内存中保留上一条输入状态最多 3 分钟。回到同一个输入框后，只有新上屏或新编辑的文字才会重新判断口令；超过 3 分钟会重新建立初始状态。

## 口令与豆包输入法

- 默认口令为 `Bingo`。“选择常用口令”提供 `Bingo`、`Submit`、`Send`、`发送`、`提交`、`完成`、`确认`、`确定`，也可直接填写自定义口令，需包含文字或数字，最多 40 个字符，不能以标点结尾或包含换行。**每次只启用一个口令**，选择预设会替换当前口令；英文大小写不敏感，`BINGO` 无需单独再加一项。
- 只匹配正文末尾的完整口令，英文忽略大小写，允许末尾有空白和标点。正文只有口令时不触发。
- 光标必须在末尾，且没有选中文字。默认等待文字稳定 1 秒，可调为 0.5～3 秒；增量上屏较慢时可适当调长。
- 工具读回核验完整正文、聚焦输入框和末尾光标。默认保留模式确认内容未变后，向原目标应用发出配置的发送按键，口令、标点和其他正文均原样保留；可选移除模式会在编辑后读回核验，再发出发送按键。

豆包必须先把文字写入目标输入框。Bingo Send **不能替豆包结束录音**，也无法仅凭文字判断录音是否已经结束。如果豆包只在你手动结束录音后才上屏，口令就只能在上屏后触发；如果持续上屏，说完口令后继续讲话仍可能提前触发，请结合稳定等待时间试用。

## 可选的口令移除

“发送前移除句尾口令”默认关闭。旧配置没有这项设置时也默认关闭；保持关闭即可原样保留完整正文和口令。

主动开启后，只移除匹配的句尾口令及其后的全部标点和空白，更早的正文、标点、空白与正文中间的口令均保留。例如，`检查 Bingo 的用法，Bingo。` 会变为 `检查 Bingo 的用法，`，中间的 Bingo 和句尾口令之前的逗号都保留。

移除会修改聚焦草稿，也可能改变选区。程序先核验原草稿和上下文，在编辑器支持时执行编辑，然后在发出发送按键前读回核验剩余正文、焦点、光标和网页上下文。只检测模式即使开启此项也不会编辑，因此检测成功后，还需用无关紧要的新消息验证实际移除。

编辑器不支持或无法核验编辑结果、上下文变化时，程序停止并暂停，不发送。若编辑后发生中断，可能留下已改草稿或选区，请检查原输入框后再试；程序不会自动恢复旧文字而覆盖可能更新的输入。每个应用或网站的保留与移除模式都应分别验证，两种模式均不使用剪贴板。

## 常见问题

**检测到了，但没有发送？**

先确认已关闭“只检测，不发送”。再核对该应用的发送按键、聊天框状态，以及浏览器域名设置。状态显示“已发出发送按键”只表示按键已发出，目标应用仍可能因为网络、发送按钮状态或快捷键配置而没有完成发送，应以目标应用实际结果为准。

**提示中止或失败，要看哪里？**

窗口顶部的“最近一次结果”会保留操作结果。失败提示会说明焦点变化、正文变化、光标位置变化等具体原因；记录不包含输入正文。

遇到失败，先暂停工具并检查原草稿，再按提示处理。开启移除模式时，草稿或选区可能已经变化；若无法确认预期正文、焦点和光标，工具不会发送。请勿把失败状态当作消息已经发出。

**一直检测不到？**

确认辅助功能已授权、总开关和目标应用已启用，随后在目标输入框输入一条新内容。让文字先上屏，取消文字选择，并把光标放到末尾。查看窗口状态提示和顶部“最近一次结果”；若输入框没有公开所需的辅助功能能力，本版本会停止处理该输入框。

**系统辅助功能开关已经打开，程序仍提示未授权？**

重新编译或替换 ad-hoc 临时签名应用可能改变本机签名。系统列表中的旧条目即使显示开启，当前程序也可能没有获得授权。

1. 完全退出 Bingo Send。
2. 在 **系统设置 → 隐私与安全性 → 辅助功能** 中移除旧的 Bingo Send 条目，再从长期安装位置（例如 `/Applications/Bingo Send.app`）添加当前应用并开启权限。
3. 重新打开 Bingo Send，检查应用中的授权状态。

如果旧条目无法移除，或系统仍沿用旧签名，可选择只重置 Bingo Send 的辅助功能授权。先退出应用，再在终端执行：

```sh
tccutil reset Accessibility io.local.bingosend
```

此命令会撤销 Bingo Send 的辅助功能权限，需要重新授予；不会重置其他应用的授权，也不会清除已保存的口令和应用名单。随后重开 Bingo Send，点“去授权…”，再由你亲自在系统“辅助功能”列表中开启当前应用。每次启动默认暂停，确认授权后再打开“启用口令发送”。

**“试用口令”成功，就代表目标应用可用了？**

“试用口令”只检查口令匹配并在本地预览，不读取或编辑其他应用，也不发送消息。目标应用的读取能力应通过“只检测”验证，保留或移除模式下的实际发送还需要在目标应用中另行确认。

**会录音、联网或保存聊天内容吗？**

Bingo Send 不录音、不联网、不保存输入正文。运行时只在内存中短暂处理允许范围内的输入框文本。应用名单、口令和等待时间等设置保存在本机 `UserDefaults`，标识为 `io.local.bingosend`。语音识别及其数据处理仍由你所用的输入法负责。

## 停止与卸载

临时停用：从菜单栏关闭“启用口令发送”。完全停止：选择“退出 Bingo Send”；仅关闭设置窗口仍会保留菜单栏工具。

卸载时先退出，再删除 `Bingo Send.app`。可在系统“辅助功能”列表中移除它。若还要清除已保存的口令和应用名单，退出后在终端执行：

```sh
defaults delete io.local.bingosend
```

应用未添加登录启动项；删除应用后不会继续运行。
