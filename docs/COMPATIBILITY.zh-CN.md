## 保留模式与移除模式

历史保留模式测试只验证读取草稿并发出发送按键，不涉及编辑草稿。1.2.0（build 9）的默认保留与可选“发送前移除句尾口令”均在上表的本地 WKWebView 编辑器通过实际发送测试，不代表 Codex 或其他 AI 应用支持移除；移除要求辅助功能编辑支持，必须在每个编辑器中单独验证。只检测模式不会验证编辑能力。

移除默认关闭，旧配置缺少此设置时也默认为关闭。开启后仅移除匹配的句尾口令及其后的标点和空白，再读回核验正文及上下文后发送。编辑器不支持或核验失败时，程序暂停且不发送；编辑后发生中断可能留下已改草稿或选区，用户应检查原输入框后再试，程序不会自动恢复旧文字而覆盖可能更新的输入。

## 配置预设不等于测试结果

1.2.0 提供 13 个需主动添加的预设：Codex / ChatGPT、Claude / Claude Code、Gemini、Grok、Cursor、HuggingChat、DeepSeek / DeepSeek Harness、ZCode、Kimi、Kimi Code、WorkBuddy、Qoder CN、TRAE CN。它们帮助填写已知的原生应用标识或建议的网站主机，详见[预设配置表](USER_GUIDE.zh-CN.md#应用和网站预设)。知道产品域名或已安装应用标识，只能确定配置目标，不代表已成功读取辅助功能信息或完成发送。

真实 AI 应用只有上表中历史版本的 Codex 桌面实测结果；其他原生应用与全部预设网站仍需单独验证。Claude Code 和 Kimi Code 名称不代表终端 CLI 编辑器已兼容，已核对的原生应用标识也不会自动覆盖其他版本。

网页预设让用户选择已安装的浏览器，并向其已有允许名单追加域名。同一浏览器的全部允许网站共用一个发送键，域名限制匹配主机及子域名，不细分网址路径。即使该浏览器中的一个网站可用，其他网站仍应逐个测试。全新安装不会主动启用任何应用；已有保存配置保持原样。

## 验证一个新应用

1. 选择应用或网站预设，或手动添加并启用目标 `.app`，核对 Return / Command-Return / Control-Return。
2. 网页预设需选择已安装浏览器，核对合并后的允许域名和共用发送键；手动添加未被识别的浏览器时，请打开“按网页域名限制”。
3. 启用总开关，先用“只检测，不发送”验证一条新输入。光标留在末尾，无文字选择。
4. 保持移除关闭，关闭只检测，再用无隐私的新测试句确认实际发送，核对收到的完整正文及当前口令。需要移除时，再单独开启并测试：确认只删掉句尾口令及其后分隔内容，更早的正文和标点仍保留。
5. 在 Issue 中报告 macOS、芯片、Bingo Send 和目标应用版本、发送键及固定状态提示，说明语音输入法和是否持续上屏。无需提供真实聊天。

程序要求可读取的 `AXValue` 和 `AXSelectedTextRange`。新进入输入框时已有的草稿只作基线，不会立即发送。不能读出控件、光标或受限制页面地址时，程序停止处理该输入框，不做猜测。
