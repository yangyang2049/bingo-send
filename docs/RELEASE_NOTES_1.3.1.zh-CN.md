# Bingo Send 1.3.1（build 12）待测版

2026-10-30。本版包含尚未正式发布的 1.3.0 多口令功能。

## 改了什么

- 最多同时配置 3 个口令，按界面语言提供中文、英文或中英混用快捷组；保留旧用户已有口令。
- 原来的「启用口令发送」和「只检测，不发送」合并为一个运行模式：**暂停／测试识别／自动发送**。
- 顶栏和菜单图标显示真实模式。权限失效、口令无效或没有启用应用时会显示受阻；暂停始终可选。
- 测试识别只提示音，不修改、不发送；移除选项此时禁用并说明原因。自动发送才按移除设置处理。
- 口令预览明确本页不发送、不验证编辑器兼容性；测试模式保留原文。修改示例、口令、模式或移除设置后，旧预览结果清空。
- 发送错误记录包含目标应用名；说明页补充“目标应用模型不可用或发送按钮禁用也会阻止发送”。
- 每次启动仍暂停；已有口令、应用规则、按键、延迟和移除设置保留。更改配置或模式后，需要在目标输入框输入一条新内容。

## 请按这个顺序测

准备：升级后先确认辅助功能仍有效；若系统要求重新授权，请由本人在系统设置完成。确认目标应用有可用模型，自己的发送按钮可用。使用无关紧要的新测试消息，光标在末尾且无选区。

| 项目 | 操作 | 期望 |
| --- | --- | --- |
| 配置保留 | 打开新版检查两个自定义口令及应用列表 | 原配置不变，顶栏显示暂停 |
| 测试识别 | 选择测试识别；到 Codex 输入新正文加口令 | 只提示音，口令和正文完整保留，没有发出消息；顶栏明确测试识别 |
| 保留发送 | 暂停，关闭移除；选自动发送，输入另一条新消息 | 消息连同末尾口令发出一次；以目标应用实际结果为准 |
| 移除发送 | 开启移除，再输入含有中间口令和末尾口令的新消息 | 只移除末尾命中的口令与尾随分隔内容；中间正文不变；发出一次 |
| 两个应用 | 在 DeepSeek Harness 重做识别、保留和移除三项 | 各自确认实际结果，不沿用 Codex 的兼容性结论 |
| ZCode | 先确保能手动发送，再做上述三项 | 模型未就绪、按钮禁用时不能据此判断 Bingo Send 兼容性 |
| 暂停 | 选择暂停后在目标应用输入新测试消息 | 不提示音、不改字、不发送 |
| 预览失效 | 在试用口令页检查，再修改示例；返回设置改口令／移除／模式 | 旧结果消失，需要重新检查；测试模式预览不移除 |
| 重启 | 退出并重开 Bingo Send | 回到暂停，保存配置不变，不自动处理已有草稿 |

## 验证边界

本版自动化测试、构建、安装与 UI 检查结果以本次交付记录为准。用户先前报告 1.3.0 在 Codex 和 DeepSeek 可发送；这不等于 1.3.1 的逐应用回归已完成。ZCode 当前实测模型未就绪、发送按钮禁用，真实发送待条件具备后由用户验证。

发出发送按键不等于消息已送达；本版没有绕过目标应用的禁用状态，也没有新增自动重试。安装包为 ad-hoc 签名，未经 Apple 公证；通用构建不等于 Intel 或最低系统实机已测。正式发布前完成上表实际发送回归。
